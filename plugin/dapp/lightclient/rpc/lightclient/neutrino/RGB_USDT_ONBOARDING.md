# RGB USDT 接入需求单（对接 Tether / UTEXO）

> 用途：对外沟通用的接入请求。本文只提**我们需要的输入**与**我们承诺做的动作**，不涉及商务条款。
> 标注 `[内部]` 的行是我方实现细节，对外发送前可删。

---

## 0. 一句话结论

我们要的**不是你们的代码、SDK 或接口对接**，而是 **RGB USDT 这个合约的权威标识 + 可独立验证的合约数据（genesis consignment）**。

拿到这两样后，链路即可闭环：RGB 的验证模型是**客户端侧验证**——任何一方只要握有合约的创世数据，就能在本地独立推导合约 id、独立校验每一笔转账，不需要信任、也不需要持续调用发行方或任何第三方服务。

因此本需求单的核心是**一份数据 + 一个标识**，而不是一次系统集成。

## 1. 背景（我方是谁、要做什么）

- 我方运营一条 Bitcoin ↔ Chain33 的跨链桥，已上线 BTC 跨链；现扩展至 **RGB 资产**，首个目标是 **RGB 上的 USDT**。
- 技术栈：**RGB v0.11.1**（侧车基于 `rgb-* 0.11.1-rc.11`），侧车自持 TSS 门限签名与 Bitcoin 索引，**自行完成 RGB 客户端侧验证**，不依赖外部验证服务。
- 桥的形态：用户在 Bitcoin 侧把 USDT 转入桥地址 → 桥在 Chain33 侧 1:1 铸造封装资产；反向为提现。桥**不发行 USDT**，只搬运现有的 USDT 合约状态。

## 3. 我方要做的（不需要贵方投入）

| 项 | 状态 | 说明 |
|---|---|---|
| 侧车支持"**adopt 外部合约**" | **改造中** | 侧车原先只能自己发行合约（即只能认识自己造的合约）；现已改造为**单一接入路径**：投喂任意合约的 genesis consignment → 解析 → 校验 → 登记。自身发行也走同一条路径，不存在特权后门。 |
| 合约身份校验（充值路径） | 机制已有，**待配置真实合约** | 每笔充值在"落账前 / 提交铸造前 / 签名节点签名前"三处都比对资产身份；未配置合约标识时降级为显式告警。接入时把 USDT 的 contractId 写入配置即生效。 |
| schema 适配 | **取决于 §4 的结果** | 我方验证配置当前以 IFA（`InflatableFungibleAsset`）的类型集合为信任集；发票构造处的 schema 标识目前也是 IFA。**若 USDT 使用其他 schema，这两处需要按实际 schema 改造。** `[内部]` |
| 精度与最小单位接线 | 待元数据 | 侧车从合约自述读取精度（adopt 路径不受我方发行路径的精度枚举限制），桥侧配置需同步。 |
| 主网运行前置 | 待确认 | 校验创世 consignment 需要能解析**主网锚定交易**的 Bitcoin 后端；我方需确认主网节点/索引的资源与配置。 |

## 4. 接单后的第一件事（我方，可当天完成）

拿到第 2 项（genesis consignment）后，我方**第一步不做任何代码改动**，而是直接跑一次现有的只读校验：

- **动作**：把 consignment 字节投给我方侧车已有的只读验证入口（gRPC `ValidateConsignment`）。该接口是**确定性、无副作用**的：不写状态、不碰私钥，只回答"这份合约数据是否自洽、其身份是什么"。`[内部] rgb-sidecar/src/engine.rs:935`
- **前置**：一个配置为主网、且能解析主网锚定交易（创世那笔 UTXO）的侧车实例。校验需要解析创世锚点的见证交易，因此**只用离线文件不够**，这一点我方会提前准备好。
- **判据**：

  | 结果 | 含义 | 后续工作量 |
  |---|---|---|
  | **通过** | schema 与类型集兼容，合约数据自洽 | **≈ 1 天**：接线 + 配置 + 一次端到端回归 |
  | **不通过**（如报"类型不在信任集内"或解析失败） | 需要按实际 schema 做适配 | **≈ 3–5 天**：扩展验证类型集 + 调整发票构造 + 回归 |

- **产出**：一条可复现的命令 + **原始输出全文**（成功或失败的原文），双方据此对齐，避免"我们这边通不过"这类无信息量的往返。

**这也是本需求单唯一真正关键的动作**——其余都是拿到数据后的例行接线。

## 附：术语约定

| 术语 | 本文含义 |
|---|---|
| **contractId / assetId** | RGB 合约的全局标识（`rgb:...`），由创世数据派生，全球唯一，不可伪造。 |
| **genesis consignment** | 合约的创世状态数据包：合约的"出生证明"，客户端验证的唯一输入。 |
| **创世 outpoint** | 合约在 Bitcoin 上锚定的那笔 UTXO（`txid:vout`），合约身份的原点。 |
| **客户端侧验证** | RGB 的验证模型：各方在本地独立校验，不依赖第三方确认。 |
| **schema / interface** | 合约遵循的数据结构与规则模板（如 IFA），决定合约支持哪些操作与字段。 |
