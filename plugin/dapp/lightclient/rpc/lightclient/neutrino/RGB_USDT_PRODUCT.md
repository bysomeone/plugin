# RGB20 USDT 跨链桥 — 产品方案

**版本**: v2.0
**目标读者**: 产品经理、业务方、非技术干系人
**最后更新**: 2026-07-23

---

## 一句话概述

> 让 Bitcoin 网络上通过 RGB 协议发行的 USDT，能够跨链到 Chain33 生态中流通使用。

---

## 1. 背景

### 1.1 我们已有 BTC 跨链桥

当前跨链桥支持 **BTC 原生币**在 Bitcoin 和 Chain33 之间双向流通：

```
BTC 链                          Chain33 链
───────                         ──────────
用户有 BTC  ──(充值)──▶  获得 wrapped BTC（可在 Chain33 生态使用）
用户想提现   ◀──(提现)──  销毁 wrapped BTC → 拿回 BTC
```

### 1.2 为什么需要 RGB20 USDT 桥

- **Bitcoin 生态发展**：RGB 协议让 Bitcoin 网络也能发行 USDT 等稳定币，是 BTC 二层生态的重要方向
- **Chain33 生态需要稳定币**：稳定币是 DeFi、支付场景的基础资产，当前 Chain33 生态缺少这一关键品类
- **与 Ethereum USDT 桥互补**：Ethereum USDT 更快，RGB USDT 更安全（继承 Bitcoin PoW）

---

## 2. 产品目标

### 双向流通

| 方向 | 用户操作 | 结果 |
|------|---------|------|
| **充值** | 用 RGB 钱包将 RGB20 USDT 转到桥地址 | Chain33 上收到 X.RGB20_USDT |
| **提现** | 在 Chain33 发起提现 | BTC 钱包收到 RGB20 USDT |
| **生态使用** | 持有 X.RGB20_USDT | 可在 Chain33 生态中转账、交易、参与 DeFi |

### 核心指标

- 充值确认时间：~1 小时（6 个 BTC 区块确认）
- 提现确认时间：~1 小时
- 费用：仅 BTC 网络矿工费 + Chain33 Gas 费，桥本身不收费
- 最小充值/提现：1 USDT

## 3. 用户视角：充值 & 提现

### 3.1 充值（BTC → Chain33）

```
第一步: 用户在 RGB 钱包操作
  │
  │  转账 RGB20 USDT 到桥的 TSS 地址
  │  备注中填写自己的 Chain33 收款地址
  │
  ▼
第二步: 等待确认（后台全自动，约 1 小时）
  │
  │  ✅ BTC 交易获得 6 个区块确认
  │  ✅ RGB 转账验证通过
  │  ✅ 多个节点独立确认一致
  │
  ▼
第三步: 到账
  │
  │  Chain33 钱包收到 X.RGB20_USDT（1:1 锚定）
```

**用户只需做第一步**，其余全自动。

### 3.2 提现（Chain33 → BTC）

```
第一步: 在 Chain33 钱包发起提现
  │
  │  填写金额和目标 BTC 地址
  │  wrapped USDT 被锁定
  │
  ▼
第二步: 等待处理（后台全自动，约 1 小时）
  │
  │  桥节点构造 BTC 交易（含 RGB 转账数据）
  │  多节点协同签名（TSS）
  │  广播到 Bitcoin 网络，等待确认
  │
  ▼
第三步: 到账
  │
  │  BTC 钱包收到 RGB20 USDT
```

**用户只需做第一步**，其余全自动。

## 4. 安全机制

### 4.1 三重验证（充值）

```
第一重（链上）: BTC 交易确实在区块中 → SPV 数学证明
第二重（链下）: RGB 转账数据合法 → 专业验证引擎
第三重（链下）: 多节点一致 → ≥ 5/7 个节点独立确认
```

任何一重不通过 → 充值被拒绝。

### 4.2 TSS 阈值签名（提现）

桥上资金不是由某一个人或某一台服务器控制：

```
7 个节点各自持有密钥碎片
至少 5 个同意 → 才能转出
任何单个节点被攻破 → 资金安全
```

### 4.3 防攻击

| 攻击尝试 | 能否得逞 | 原因 |
|---------|---------|------|
| 伪造一笔 RGB 充值 | ❌ | RGB 验证不通过 |
| 修改充值金额 | ❌ | 金额从 RGB 转账数据中提取，无法篡改 |
| 同一笔充值提交两次 | ❌ | 系统记录已处理 |
| 桥节点想偷钱 | ❌ | 需要至少 5 个节点同时签名 |

## 5. 与现有跨链桥对比

| | BTC 桥（已有） | RGB USDT 桥（本方案） | Ethereum USDT 桥（已有） |
|---|---|---|---|
| **跨链资产** | BTC 原生币 | RGB20 USDT | ERC-20 USDT |
| **底层网络** | Bitcoin | Bitcoin | Ethereum |

| **费用波动** | BTC 矿工费 | BTC 矿工费（可预测） | ETH Gas（波动大） |
| **用户操作** | 转 BTC 到桥地址 | 转 RGB20 USDT 到桥地址 | 转 ERC-20 USDT 到桥地址 |

```
                    ┌──────────────────────┐
                    │    Chain33 生态       │
 BTC 链             │                      │
 ───────            │  支付  │ DeFi │ 交易  │
                    │    │      │      │    │
```

- **差异化优势**：RGB USDT 比 Ethereum USDT 更安全，比 TRON USDT 更去中心化

## 8. 常见问题

**Q: 用户需要懂 RGB 协议吗？**
A: 不需要。和普通 USDT 转账一样，钱包会处理好所有细节。

**Q: 和 Ethereum USDT 桥有什么不同？**
A: RGB USDT 基于 Bitcoin 网络，安全性更高；Ethereum USDT 基于以太坊，确认更快。两者互补。

**Q: 桥本身收费吗？**
A: 不收费。用户只需支付 BTC 网络矿工费和 Chain33 Gas 费。

**Q: 为什么确认需要 ~1 小时？**
A: Bitcoin 网络需要 6 个区块确认（约 1 小时）才能认为交易不可逆转，这是在安全性和速度之间的标准权衡。

**Q: 桥中的资金安全吗？**
A: 三重安全机制：链上 SPV 验证 + RGB 协议验证 + 7 节点 5 签名。单一节点受损不影响整体安全。

## 9. 术语速查

| 术语 | 一句话解释 |
|------|-----------|
| **RGB 协议** | 在 Bitcoin 上发行代币的技术标准，类似 Ethereum 上的 ERC-20 |
| **RGB20** | RGB 协议中"同质化代币"的标准 |
| **RGB USDT** | 通过 RGB 协议在 Bitcoin 网络上发行的 USDT 稳定币 |
| **X.RGB20_USDT** | RGB USDT 跨链到 Chain33 后的封装资产名称，1:1 锚定 |
| **TSS** | 多方共同管理资产的密码学技术，没有单一私钥 |
| **SPV** | 轻量级验证技术，无需下载全量 BTC 数据即可验证交易 |
| **DKG** | TSS 的初始化流程，生成多方持有的密钥碎片 |
