# RGB USDT 跨链桥 — 产品方案

**版本**: v1.0  
**目标读者**: 产品经理、业务方、非技术干系人  
**最后更新**: 2026-07-23

---

## 一句话概述

> 让 Bitcoin 网络上通过 RGB 协议发行的 USDT，能够安全地跨链到 Chain33 生态中流通使用。

---

## 1. 背景

### 1.1 我们已有 BTC 跨链桥

当前跨链桥已经支持 **BTC 原生币** 在 Bitcoin 和 Chain33 之间双向流通：

```
BTC 链                          Chain33 链
───────                         ──────────
用户有 BTC  ──(充值)──▶  获得 wrapped BTC（可在 Chain33 生态使用）
用户想提现   ◀──(提现)──  销毁 wrapped BTC → 拿回 BTC
```

### 1.2 为什么需要 RGB USDT

- **市场需求**：USDT（泰达币）是加密世界流通量最大、使用最广泛的稳定币
- **Bitcoin 生态扩展**：RGB 协议让 Bitcoin 网络也能发行 USDT 等稳定币，这是 BTC 二层生态的重要方向
- **Chain33 生态需求**：Chain33 生态需要稳定币作为交易媒介、DeFi 基础资产

### 1.3 Bitcoin 上的 USDT 有什么特别

传统 USDT 主要在 Ethereum / TRON 上发行。**RGB USDT** 是发行在 Bitcoin 网络上的版本，有以下特点：

- 安全性继承 Bitcoin 网络（最安全的 PoW 链）
- 隐私性更好（RGB 采用客户端验证，交易数据不上全链）
- 手续费以 BTC 计价（不依赖 ETH 等代币支付 Gas）

## 2. 产品目标

### 一句话：让 RGB USDT 像 BTC 一样在 Chain33 中自由流转

| 方向 | 用户操作 | 结果 |
|------|---------|------|
| **充值** | 用户在 BTC 钱包将 RGB USDT 转到桥地址 | Chain33 上收到等量 wrapped USDT |
| **提现** | 用户在 Chain33 发起提现 | BTC 钱包收到等量 RGB USDT |
| **生态使用** | 持有 wrapped USDT 的用户 | 可在 Chain33 生态中转账、交易、参与 DeFi |

### 核心指标

- 充值确认时间：~1 小时（6 个 BTC 区块确认）
- 提现确认时间：~1 小时（6 个 BTC 区块确认 + TSS 签名协调）
- 充值手续费：仅 BTC 网络矿工费（无额外桥费用）
- 提现手续费：BTC 网络矿工费 + Chain33 Gas 费
- 支持的最小充值/提现：1 USDT

## 3. 用户视角：充值 & 提现流程

### 3.1 充值（BTC → Chain33）

```
第一步: 打开 RGB 钱包
  │
  │  [用户操作] 发起 RGB USDT 转账，收款地址填写桥的 TSS 地址
  │            在备注/OP_RETURN 中填入自己的 Chain33 收款地址
  │
  ▼
第二步: 等待确认（后台自动）
  │
  │  [系统自动] 桥节点监听 BTC 网络，检测到这笔转账
  │  [系统自动] 验证 RGB USDT 状态转移有效
  │  [系统自动] 等待 6 个区块确认（约 1 小时）
  │
  ▼
第三步: 到账
  │
  │  [用户可见] Chain33 钱包中收到 wrapped USDT
  │  [用户操作] 可在 Chain33 生态中使用（转账、交易、理财等）
```

**用户只需要做第一步**，其余全自动。

### 3.2 提现（Chain33 → BTC）

```
第一步: 在 Chain33 钱包发起提现
  │
  │  [用户操作] 填写提现金额和目标 BTC 地址
  │  [链上操作] wrapped USDT 被锁定
  │
  ▼
第二步: 等待处理（后台自动）
  │
  │  [系统自动] 桥节点检测到提现请求
  │  [系统自动] 多个节点协作签名（TSS 阈值签名，保证安全）
  │  [系统自动] 广播 BTC 交易到 Bitcoin 网络
  │  [系统自动] 等待 6 个区块确认（约 1 小时）
  │
  ▼
第三步: 到账
  │
  │  [用户可见] BTC 钱包中收到 RGB USDT
  │  [系统自动] 后台完成结算，锁定资产被销毁
```

**用户只需要做第一步**，其余全自动。

## 4. 安全机制（通俗版）

### 4.1 没有"单点控制"—— TSS 多签

桥上的资金不是由某一个人或某一台服务器控制的。

```
传统方式:
  一把私钥 → 谁拿到谁就能转走钱 → 风险高

我们的方式 (TSS 阈值签名):
  7 个节点各自持有一份密钥碎片
  至少 5 个节点同意 → 才能转出资金
  任何一个节点被攻击 → 钱还是安全的
```

### 4.2 充值防伪造—— SPV 验证

攻击者无法伪造一笔不存在的充值来骗取 wrapped USDT：

```
系统验证了什么:
  ✅ 这笔 BTC 交易真的存在？（查 BTC 区块记录）
  ✅ 交易金额对吗？（检查 RGB 状态转移）
  ✅ 收款地址是我们的桥地址吗？
  ✅ 备注信息正确吗？（确保充值到正确的 Chain33 地址）
  ✅ 等够 6 个区块了吗？（防止交易被 BTC 网络回滚）
```

### 4.3 提现防双花—— Sticky 机制

同一笔提现请求，所有重试必须使用同一个资金来源，防止被重复提现：

```
如果桥节点第一次签名失败需要重试:
  ✅ 资金来源必须和第一次相同
  ❌ 不允许换成另一笔钱重新构造交易
  → 其他独立节点会检查这一点，不一致就拒绝签名
```

| 攻击尝试 | 能否得逞 | 原因 |
|---------|---------|------|
| 伪造一笔充值 | ❌ | SPV 验证不通过 |
| 重复提交同一笔充值 | ❌ | 系统记录已处理，拒绝重复 |
| 篡改提现金额 | ❌ | 链上记录金额，无法修改 |
| 桥节点尝试构造双花交易 | ❌ | 至少 5 个节点签名才生效，独立节点会检查 |
| 同时攻击 3 个以上节点 | ⚠️ 理论风险 | 需要同时攻破 5 个独立节点，实际极难 |

## 5. 与现有 BTC 桥的对比

| | BTC 桥 | RGB USDT 桥 |
|---|---|---|
| **跨链资产** | BTC 原生币 | RGB USDT |
| **用户操作** | 转账 BTC 到桥地址 | 转账 RGB USDT 到桥地址 |
| **确认时间** | ~1 小时 | ~1 小时 |
| **安全性** | TSS 多签 + SPV | TSS 多签 + SPV + RGB 验证 |
| **链上手续费** | BTC 矿工费 | BTC 矿工费 |
| **额外成本** | 无 | 无（桥本身不收费） |

**对用户来说体验基本一致**，技术实现上的差异对用户透明。

## 6. 与 Ethereum USDT 桥的对比

| | RGB USDT 桥 (本方案) | Ethereum USDT 桥 (已有 cross2eth) |
|---|---|---|
| **底层网络** | Bitcoin | Ethereum / EVM 兼容链 |
| **安全性** | 继承 Bitcoin PoW 安全性 | 继承 Ethereum PoS 安全性 |
| **确认速度** | ~1 小时（6 个区块） | ~3-5 分钟（12 个区块） |
| **网络拥堵** | BTC 链上流量影响费用 | ETH Gas 价格波动大 |
| **隐私保护** | 更好（RGB 客户端验证） | 交易数据全链可见 |

**两者互补**：Ethereum USDT 更快，RGB USDT 更安全更隐私。

## 9. 常见问题

**Q: 用户需要懂 RGB 协议吗？**
A: 不需要。用户操作和普通 USDT 转账一样，钱包会处理好 RGB 相关细节。

**Q: 充值/提现有金额限制吗？**
A: 最小 1 USDT，上限根据桥中资金池余额动态调整。初期会设置日限额，后续根据运行情况调整。

**Q: 如果充值后很久没到账怎么办？**
A: 通常 1 小时左右到账。如果超过 2 小时，可能 BTC 网络拥堵导致确认慢，或交易未被正常检测。可联系技术支持查询。

**Q: 桥本身收费吗？**
A: 桥不收取额外费用。用户只需支付 BTC 网络矿工费和 Chain33 Gas 费。

**Q: 桥中的 USDT 安全吗？**
A: 资金由 7 个独立节点共同管理，至少需要 5 个节点签名才能动用。任何单一节点被攻击都无法转走资金。

## 10. 术语速查

| 术语 | 一句话解释 |
|------|-----------|
| **RGB 协议** | 在 Bitcoin 上发行代币的技术标准，类似 Ethereum 上的 ERC-20 |
| **RGB USDT** | 通过 RGB 协议在 Bitcoin 网络上发行的 USDT 稳定币 |
| **wrapped USDT** | RGB USDT 跨链到 Chain33 后的代币名称，1:1 锚定 |
| **TSS** | 多方共同管理资产的密码学技术，没有单一私钥 |
| **SPV** | 轻量级验证技术，无需下载全量 BTC 数据即可验证交易 |
| **封印 / Seal** | RGB 协议中锁定资产所有权的 Bitcoin UTXO |
| **桥节点** | 运行跨链桥服务的服务器，负责监听和构造交易 |
| **DKG** | TSS 的初始化流程，生成多方持有的密钥碎片 |
