# RGB20 USDT 跨链桥 — 产品方案

**版本**: v2.0  
**目标读者**: 产品经理、业务方、非技术干系人  
**最后更新**: 2026-07-23

---

## 一句话概述

> 让 Bitcoin 网络上通过 RGB 标准协议发行的 USDT（RGB20），能够跨链到 Chain33 生态中流通使用。

---

## 1. 背景

### 1.1 我们已有 BTC 跨链桥

当前跨链桥通过 **rgbx 协议**支持 BTC 原生币在 Bitcoin 和 Chain33 之间双向流通。

> **注意**：rgbx 是 Chain33 生态自研的资产协议，借用了 RGB 的设计思想，但和 LNP/BP 协会维护的 **RGB 标准协议**不兼容。两者是不同的系统。

### 1.2 为什么需要 RGB20 USDT 桥

- **Bitcoin 生态正在发展 RGB 稳定币**：RGB20 是 RGB 标准协议定义的同质化代币标准，USDT 是其中最受关注的资产
- **Chain33 生态需要稳定币**：作为 DeFi、支付场景的基础资产
- **与现有的 Ethereum USDT 桥互补**：Ethereum USDT 更快，RGB20 USDT 更安全（继承 Bitcoin PoW）

### 1.3 核心挑战

rgbx 和 RGB 标准协议**说不同的"语言"**。要在两者之间建桥，需要在中间加一层"翻译"——这就是 **RGB20 适配层**。

```
RGB 标准协议                 适配层                rgbx 协议
═════════════    翻译/验证    ═══════    提交      ══════════
"RGB20 USDT"   ──────────▶  neutrino   ────────▶  "X.RGB20_USDT"
(OPRET承诺)                 官方节点               (链上封装资产)
```

## 2. 产品目标

### 双向流通

| 方向 | 用户操作 | 结果 |
|------|---------|------|
| **充值** | 用 RGB 钱包将 RGB20 USDT 转到桥地址 | Chain33 上收到 X.RGB20_USDT |
| **提现** | 在 Chain33 发起提现 | BTC 钱包收到 RGB20 USDT |

### 核心指标

- 充值确认时间：~1 小时（6 个 BTC 区块确认）
- 提现确认时间：~1 小时
- 费用：仅 BTC 网络矿工费 + Chain33 Gas 费，桥本身不收费
- 最小充值/提现：1 USDT

## 3. 用户视角：充值 & 提现

### 3.1 充值（BTC → Chain33）

```
第一步: 用户在 RGB 钱包操作
  │
  │  转账 RGB20 USDT 到桥的 TSS 地址
  │  在备注中填写自己的 Chain33 收款地址
  │
  ▼
第二步: 等待确认（后台全自动，约 1 小时）
  │
  │  ✅ BTC 交易获得 6 个区块确认
  │  ✅ RGB 协议验证通过（金额正确、无双重支付）
  │  ✅ 多个节点独立确认一致
  │
  ▼
第三步: 到账
  │
  │  Chain33 钱包收到 X.RGB20_USDT（1:1 锚定）
```

### 3.2 提现（Chain33 → BTC）

```
第一步: 在 Chain33 钱包发起提现
  │
  │  填写金额和目标 BTC 地址
  │  wrapped USDT 被锁定
  │
  ▼
第二步: 等待处理（后台全自动，约 1 小时）
  │
  │  桥节点构造 BTC 交易（含 RGB 状态转移数据）
  │  多节点协同签名（TSS）
  │  广播到 Bitcoin 网络，等待确认
  │
  ▼
第三步: 到账
  │
  │  BTC 钱包收到 RGB20 USDT
```

**用户只需做第一步，其余全自动。**

## 4. 安全机制

### 4.1 三重验证（充值）

```
第一重（链上）: BTC 交易确实在区块中 → SPV 数学证明
第二重（链下）: RGB 状态转移合法 → RGB Core 验证引擎
第三重（链下）: 多节点一致 → ≥ 5/7 个节点独立确认
```

任何一重不通过 → 充值被拒绝。

### 4.2 TSS 阈值签名（提现）

桥上资金不是由某一个人或某一台服务器控制：

```
7 个节点各自持有密钥碎片
至少 5 个同意 → 才能转出
任何单个节点被攻破 → 资金安全
每个节点的签名操作都会被其他节点验证
```

### 4.3 防攻击能力

| 攻击尝试 | 能否得逞 | 原因 |
|---------|---------|------|
| 伪造一笔 RGB 充值 | ❌ | RGB Core 验证不通过 |
| 修改充值金额 | ❌ | 金额从 RGB 状态转移中提取，无法篡改 |
| 同一笔充值提交两次 | ❌ | 系统记录已处理，拒绝重复 |
| 桥节点想偷钱 | ❌ | 需要至少 5 个节点同时签名 |

## 8. 常见问题

**Q: 用户需要懂 RGB 协议吗？**
A: 不需要。用户操作和普通 USDT 转账一样，RGB 钱包会处理好协议细节。

**Q: 和 Ethereum USDT 桥有什么不同？**
A: RGB20 USDT 基于 Bitcoin 网络，安全性继承 Bitcoin PoW；Ethereum USDT 基于 Ethereum PoS。两者互补：一个更安全，一个更快。

**Q: 桥本身收费吗？**
A: 不收费。用户只需支付 BTC 网络矿工费和 Chain33 Gas 费。

**Q: 为什么确认需要 ~1 小时？**
A: Bitcoin 网络需要 6 个区块确认（约 1 小时）才能认为交易不可逆转，这是在安全性和速度之间的标准权衡。

**Q: 桥中的资金安全吗？**
A: 三重安全机制：SPV 链上验证 + RGB 协议验证 + 7 节点 5 签名。单一节点受损不影响整体安全。

| **RGB Core** | RGB 标准协议的官方 Rust 实现库 |
| **X.RGB20_USDT** | RGB20 USDT 跨链到 Chain33 后的封装资产名称 |
| **TSS** | 多方共同管理资产的密码学技术 |
| **封印 / Seal** | RGB 协议用来锁定资产的 Bitcoin UTXO |
| **Opret / Tapret** | RGB 标准协议的两种链上承诺方式 |
