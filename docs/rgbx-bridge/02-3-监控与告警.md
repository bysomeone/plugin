# 监控与告警

## 1. 健康检查

网关提供无鉴权的 `GET /healthz`：

- `200` + `{"status":"ok","deposit_api":bool,"events":bool,"metrics":bool,"data_dir_writable":bool}`
  （`metrics` = 自本次启动以来是否收到过任何桥快照）；
- 数据目录不可写时 `503` + `status:"degraded"`；
- 响应不含路径、token 或计数，可直接给容器/负载均衡探针用。

各字段含义与完整响应契约见网关
[README.md](../../plugin/dapp/lightclient/rpc/lightclient/neutrino/cmd/rgb-consignment-gateway/README.md)。
不便走 HTTP 探针时，也可 `POST` 一个无害的 `server.info` 验证 JSON-RPC（返回含 `chain_title`）。

桥本身不监听入站端口，没有自己的探针端点；桥的存活靠进程监控与下述启动/运行日志判断。

## 2. 启动自检日志

以下日志在启动阶段出现，缺失或告警时应先停下排查，不要带病放流量：

| 日志 | 含义 |
| --- | --- |
| `deposit API enabled chain-title=...` | 网关充值 API 已启用 |
| `bridge event ledger enabled` | 网关事件账本已打开 |
| `bridge metrics endpoint enabled` | 网关指标端点已注册 |
| `rgb20 metrics pusher started` | 桥开始按间隔推送指标 |
| `rgb20 gateway chain title verified` | 网关 `server.info.chain_title` 与桥的 `chainTitle` 一致 |
| `rgb20 gateway chain title mismatch: deposit requests will be rejected`（ERROR） | 两边 title 不一致，充值请求会被网关拒签，用户永远拿不到 invoice |
| `rgb20 gateway token verified` | `gatewayToken` 可读 `/bridge/events` |
| `rgb20 gateway token rejected`（ERROR，带 401/403） | token 与网关 `--bridge-token` 不一致 |
| `rgb20 gateway token self-check could not reach the gateway` / `rgb20 gateway self-check: server.info failed`（WARN） | 网络或超时，按网关可达性排查 |
| `ALERT wallet birthday cannot cover chain history` | `btcwallet.db` 被重建，历史充值不可见；立即用备份还原。启动时按本地头链高度立即检查，不必等新区块 |

网关自检在后台运行，最多 5 秒、不阻塞启动、不改启动结果——**看到 ERROR 不等于进程会退出**，必须靠
日志告警兜住。桥侧还会打印合约精度核对结果、TSS 组公钥一致性自检、头链锚点起点。

## 3. 日志关键字

必须监控的关键字（均为 ERROR/WARN，便于 grep/告警）：

| 关键字 | 含义 | 动作 |
| --- | --- | --- |
| `ALERT wallet birthday cannot cover chain history` | 新钱包无法覆盖历史 | 立即用备份还原 |
| `ALERT withdrawal circuit breaker tripped` | 提现熔断 | 停新提现，查 payout mismatch 原因 |
| `payout mismatch` / `withdraw payout mismatch` | 发票金额与手续费不符 | 查前端开票逻辑 / 链上手续费 |
| `deposit.rejected`（事件账本） | 链上拒绝铸造 | 查合约身份、签名请求、限额 |
| `insufficient BTC confirmations` | 确认数不足（通常是等待） | 观察头链是否前进 |
| `tss` / `DKG` / `share` 相关 ERROR | 签名材料/组公钥不一致 | 按 [CONFIG.md](../../plugin/dapp/lightclient/rpc/lightclient/neutrino/CONFIG.md) §4.3 处理，勿盲目重启 |

## 4. 审计事件账本

网关提供 append-only 的审计事件账本，桥在关键生命周期自动投递，统计/审计后端按游标读取。

- **接口契约**（鉴权、字段、游标、事件类型）见
  [03-前端对接.md](03-前端对接.md) §8；事件清单见 [01-系统设计.md](01-系统设计.md) §9。
- 运维只需要知道账本存在、保留期（`--events-retention`，默认 90 天）以及下面的告警用法。
- 它**不是权威账本**：链上数据为准，事件用于统计、对账与排障。

事件驱动的告警建议：

- `deposit.rejected` 连续出现 → 查合约身份、限额、用户签名请求。
- `withdraw.settled` 长时间缺失而 `withdraw.broadcast` 存在 → 查 BTC 确认与确认交易提交。
- `withdraw.unlocked` 出现 → 说明有提现走了退款路径，核对原因（发票金额、永久拒签、手工放弃）。
- `sweep.completed` 长时间缺失且主池余额下降 → 查扫集 worker 与费率上限。

## 5. 指标

桥每 `gatewayMetricsInterval`（默认 30s，`0s`/负值关闭）向网关
`POST /bridge/metrics` 推送一次运行快照；网关只保留每个 `node_id` 的**最新**快照（内存，不落盘，
重启清空），并在无鉴权的 `GET /metrics` 以 Prometheus 文本格式暴露。桥侧计数器是**进程生命周期
内**的累计值，重启归零；长期趋势由 Prometheus 保存。

指标清单：

| 指标 | 类型 | 含义 |
| --- | --- | --- |
| `rgbx_bridge_up{node}` | gauge | 最近一次快照距今 ≤120s 为 1，否则 0 |
| `rgbx_bridge_snapshot_age_seconds{node}` | gauge | 快照年龄（秒） |
| `rgbx_bridge_uptime_seconds{node}` | gauge | 桥适配器运行时长 |
| `rgbx_bridge_chain_height{node}` / `rgbx_bridge_btc_header_tip{node}` | gauge | 主链高度 / BTC 头链 tip（取不到为 0） |
| `rgbx_bridge_breaker_tripped{node}` | gauge | 提现熔断（1 = 已熔断） |
| `rgbx_bridge_sidecar_reachable{node}` | gauge | 桥与 RGB 侧车的连接是否已建立 |
| `rgbx_bridge_events_total{node,type}` | counter | 按事件类型的累计计数（含 `payout_mismatch`） |
| `rgbx_bridge_outbox_pending{node}` | gauge | 本地 outbox 待投递事件数 |
| `rgb_gateway_events_retained` / `rgb_gateway_event_last_seq` | gauge / gauge | 网关事件账本保留条数 / 最大序号 |
| `rgb_gateway_uptime_seconds` / `rgb_gateway_data_dir_writable` | gauge | 网关运行时长 / 数据目录可写 |
| `rgbx_backup_last_success_timestamp_seconds` | gauge | 最近一次成功冷备的时间（unix 秒；`0` = 无成功备份）。来自**宿主机 node_exporter textfile**，不是网关 |
| `rgbx_backup_age_seconds` | gauge | 距最近一次成功冷备的秒数（`-1` = 无成功备份）。来源同上 |

前 10 行由网关 `GET /metrics` 暴露；最后两行由 `check_backup_freshness.sh` 写入 node_exporter 的
textfile collector，与网关进程无关（cron 与采集配置见
[02-2-备份与恢复.md](02-2-备份与恢复.md) §9；上线前必须接入并实跑一次告警链路）。

`/bridge/metrics/latest` 用桥 token 或只读 `--events-token` 读取，便于排障时直接看原始快照。
完整契约见网关
[README.md](../../plugin/dapp/lightclient/rpc/lightclient/neutrino/cmd/rgb-consignment-gateway/README.md)
的 "Bridge metrics" 节。

Prometheus scrape 样例（`/metrics` 无鉴权，只对运维网开放；网关默认只听 loopback）：

```yaml
scrape_configs:
  - job_name: rgb-bridge-gateway
    scrape_interval: 30s
    static_configs:
      - targets: ["127.0.0.1:8080"]
```

建议告警规则：

```yaml
groups:
  - name: rgb-bridge
    rules:
      - alert: RgbBridgeDown
        expr: rgbx_bridge_up == 0
        for: 2m
        labels: {severity: critical}
        annotations:
          summary: "桥节点 {{ $labels.node }} 超过 120s 未上报指标"
      - alert: RgbBridgeSnapshotStale
        expr: rgbx_bridge_snapshot_age_seconds > 120
        for: 2m
        labels: {severity: warning}
        annotations:
          summary: "桥节点 {{ $labels.node }} 快照已过期 {{ $value }}s"
      - alert: RgbBridgeBreakerTripped
        expr: rgbx_bridge_breaker_tripped == 1
        labels: {severity: critical}
        annotations:
          summary: "桥节点 {{ $labels.node }} 提现熔断已触发，查 payout mismatch"
      - alert: RgbBridgeDepositRejected
        expr: increase(rgbx_bridge_events_total{type="deposit.rejected"}[10m]) > 0
        labels: {severity: warning}
        annotations:
          summary: "10 分钟内出现充值铸造被链上拒绝"
      - alert: RgbxBackupAging
        expr: time() - rgbx_backup_last_success_timestamp_seconds > 86400 and time() - rgbx_backup_last_success_timestamp_seconds <= 129600
        for: 10m
        labels: {severity: warning}
        annotations:
          summary: "最近一次成功冷备已超过 24h（RPO）"
      - alert: RgbxBackupStale
        expr: time() - rgbx_backup_last_success_timestamp_seconds > 129600
        for: 10m
        labels: {severity: critical}
        annotations:
          summary: "最近一次成功冷备超过 36h，或没有任何成功备份"
      - alert: RgbxBackupMetricMissing
        expr: absent(rgbx_backup_last_success_timestamp_seconds)
        for: 15m
        labels: {severity: warning}
        annotations:
          summary: "备份新鲜度指标不存在：cron / node_exporter textfile 未配置或已停摆"
```

备份规则用绝对时间 `time() - rgbx_backup_last_success_timestamp_seconds`：`rgbx_backup_age_seconds` 是
脚本每次运行时写死的值，cron 停摆时会冻结在旧值，而 timestamp 会随当前时间自然变大；无备份时
timestamp 为 `0`，规则同样触发。若 textfile **从未生成**（脚本没装或没跑过），两条备份规则都不会
触发，用 `absent(...)` 兜底。

备份新鲜度的采集不经过网关：由 `check_backup_freshness.sh` 写入宿主机 node_exporter 的 textfile
collector（见 [02-2-备份与恢复.md](02-2-备份与恢复.md) §9）。

## 6. 告警建议

| 级别 | 条件 | 动作 |
| --- | --- | --- |
| P1 | `/healthz` 非 200 或连续不可达 | 按 [02-4-应急预案.md](02-4-应急预案.md) 的"网关宕机"处理 |
| P1 | `ALERT wallet birthday cannot cover chain history` | 立即停节点并用备份还原 |
| P1 | `ALERT withdrawal circuit breaker tripped` | 停新提现，查 mismatch 原因 |
| P1 | `deposit.rejected` 连续出现 | 查合约身份、限额、签名请求 |
| P2 | `withdraw.settled` 在 `withdraw.broadcast` 后长时间缺失 | 查 BTC 确认与确认交易提交 |
| P2 | `sweep.completed` 长时间缺失且主池余额下降 | 查扫集 worker 与费率上限 |
| P2 | `rgbx_backup_age_seconds > 86400`（24h，超出 RPO） | 立即补做冷备并核对包自检结果 |
| P1 | `rgbx_backup_age_seconds > 129600`（36h）或 `= -1`（没有成功备份） | 立即补做冷备；若 age 冻结在旧值，用 `time() - rgbx_backup_last_success_timestamp_seconds` 判断真实年龄 |
| P1 | `rgbx_bridge_up == 0` 持续 2m，或 `rgbx_bridge_breaker_tripped == 1` | 节点失联或熔断；按 [02-4-应急预案.md](02-4-应急预案.md) 排查，熔断时先停新提现 |
| P2 | `rgbx_bridge_snapshot_age_seconds > 120` 持续 2m | 桥进程/网关链路异常，查推送日志 `rgb20 metrics push failed` |
| P2 | `increase(rgbx_bridge_events_total{type="deposit.rejected"}[10m]) > 0` | 有充值被链上拒绝，查合约身份、限额与用户签名请求 |

日志规则与指标规则并存：日志保留单次失败的细节，指标负责"持续状态"与跨节点汇总。
