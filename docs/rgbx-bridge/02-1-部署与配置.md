# 部署与配置

本文讲部署顺序、上线前必须确认的生产值，以及网关的日常运维。配置项的逐项说明见
[CONFIG.md](../../plugin/dapp/lightclient/rpc/lightclient/neutrino/CONFIG.md)。

## 1. 部署步骤

1. **主链**：部署 chain33 节点与应用（`rgbx`、`lightclient`、`autonomy`、`manage`）。
2. **BTC 节点**：btcd/bitcoin-core（生产）+ 可选的 electrs；桥通过 SPV 头链校验，不依赖第三方索引。
3. **TSS 节点**：每个节点一份 `chain33.para*.toml` + 钱包目录（authAccount 私钥）+ `addrbook/`（libp2p 身份）。
   `[wallet] dbPath` **必须在 datadir 内**，否则不在备份集里（见
   [CONFIG.md](../../plugin/dapp/lightclient/rpc/lightclient/neutrino/CONFIG.md) 与
   [02-2-备份与恢复.md](02-2-备份与恢复.md)）。
4. **侧车**：每个签名节点一个 `rgb-sidecar`，数据目录 `/data` 含 `ledger.json`、`stock` 等；同一个
   `rgb20.contracts[].assetId` 必须与链上登记一致。
5. **网关**：单实例 + 持久卷（`--data-dir`）。建议前置反向代理终止 TLS；或由网关自身 TLS。
6. **注册资产**：官方节点完成 DKG 后 `commitDKG`/`CommitDKG` 登记跨链资产；桥核对合约精度并回填
   `crossChainInfo.precision`。
7. **治理初始化**：用 `bridge-config-apply` + autonomy 审批 + `bridge-config-approve` 设置限额、暂停开关、
   RGB20 提现手续费。首次配置立即生效；之后的放松类修改有 24h 时间锁（见
   [02-5-治理与日常操作.md](02-5-治理与日常操作.md)）。

## 2. 上线前必须确认的生产值

以下任一项写成测试值，都会把桥变成"能跑但不可信"：

| 配置 | 位置 | 生产值 |
| --- | --- | --- |
| `testSignPsbt` | 桥 `rgb20` | **false**（默认）；true 等于允许签任意 PSBT |
| `testListen` | 桥 `rgb20` | **空** |
| `transportEndpoint` | 桥 `rgb20` | 公网可达的 `rpcs://...` |
| `transportGateway` + `gatewayToken` | 桥 `rgb20` | 网关内网地址 + ≥16 字符共享密钥 |
| `e2e` 专用低确认数 | 链配置 | `minBtcConfirmations`、`blockConfirmations`、`mainChainConfirmations` 按生产安全值 |
| `safety.disable*` | 桥 `rgb20.safety` | 上线后按需打开；默认关闭 |
| 网关 TLS / mTLS | 网关启动参数 | `--tls-cert/--tls-key`，建议再加 `--client-ca` |
| 网关 `--trust-proxy` | 网关 | 只有反向代理可信时打开 |
| `chainTitle` | 网关 `--chain-title` | 等于链上 `guardianParachainTitle`（平行链 Title） |
| 治理配置 | 链上 `bridgeConfig*` | 限额、暂停、手续费必须已有值，不能停在"从未配置" |

启动日志核对：网关会打印 `deposit API enabled chain-title=...`、`bridge event ledger enabled`；桥会打印
合约精度核对结果、TSS 组公钥一致性自检、头链锚点起点。任一项缺失或告警，先停下排查。日志含义见
[02-3-监控与告警.md](02-3-监控与告警.md)。

## 3. 网关运维

启动（示例）：

```bash
./rgb-consignment-gateway \
  --listen 127.0.0.1:8080 \
  --data-dir /var/lib/rgb-gateway \
  --chain-title 'user.p.rgbx.' \
  --bridge-token '<共享密钥>' \
  --events-token '<审计只读密钥>' \
  --events-retention 2160h \
  --tls-cert /etc/rgb/tls.crt --tls-key /etc/rgb/tls.key \
  --client-ca /etc/rgb/bridge-ca.pem
```

- `--bridge-token` 与 `--chain-title` 必须同时配置；`--client-ca` 需要 `--tls-cert`。
- 存储布局、保留期（consignment `--ttl` 默认 7 天、事件 `--events-retention` 默认 90 天）与重启行为
  见网关 [README.md](../../plugin/dapp/lightclient/rpc/lightclient/neutrino/cmd/rgb-consignment-gateway/README.md)
  的 "Storage and retention"；重启时索引与事件账本从磁盘重建，请求按 `request_id` 幂等。
- 网关不可用时：用户无法提交新充值请求、无法支付 invoice；桥已有的提现/确认不受影响。恢复后 SSE 会重放
  未出票请求，充值请求不会丢。

健康检查、启动自检与告警见 [02-3-监控与告警.md](02-3-监控与告警.md)。协议、鉴权与事件账本接口的权威
说明见网关 [README.md](../../plugin/dapp/lightclient/rpc/lightclient/neutrino/cmd/rgb-consignment-gateway/README.md)。
