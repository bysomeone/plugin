# 应急预案

通用原则：先判断"钱有没有动"——涉及签名/广播的路径优先止血（治理暂停或节点本地急停，见
[02-5-治理与日常操作.md](02-5-治理与日常操作.md)），再排查；**不要**清 `lightclient/` 目录、不要手动改
侧车账本、不要靠重启"修好"签名材料。

| 场景 | 处理 |
| --- | --- |
| 网关宕机 | 恢复网关；桥自动重连 SSE 并重放未出票请求；提现/确认不受影响 |
| 桥节点宕机 | 重启该节点；share/钱包/侧车从本地恢复；不要清 `lightclient/` 目录 |
| 侧车宕机 | 桥 fail-closed（不动钱）；恢复侧车后自动继续；确认 `/data` 未丢。数据范围与恢复见 [02-2-备份与恢复.md](02-2-备份与恢复.md) |
| BTC 节点落后/断连 | 桥暂停充值提交与提现广播；恢复节点后自动继续。**不要**重启 regtest btcd（会清链） |
| 主链深重组（> `mainChainConfirmations`） | 治理暂停充值/提现或本地急停 → 人工核对 pending/confirm 与侧车账本 → 按 [WITHDRAW_LOCK_MODEL.md](../../plugin/dapp/lightclient/rpc/lightclient/neutrino/WITHDRAW_LOCK_MODEL.md) 处置 |
| 提现长期 `confirmed=false` | 查 `payout mismatch`、签名轮次、BTC 广播；确认未签名前可用 `abandon-withdraw` 走解锁；已签名只能继续结算。命令见 [02-5-治理与日常操作.md](02-5-治理与日常操作.md) |
| 用户发票金额错误 | 提现停在锁定状态；按解锁路径退回，不要手动改账本 |
| 误删 `btcwallet.db` | 立即停节点，用备份还原该文件；**不要**让它新建钱包后继续跑 |
| TSS share 与链上组公钥不一致 | 节点会拒绝启动（`tss.allowShareMismatch` 默认 false）；确认备份代次后按 [02-2-备份与恢复.md](02-2-备份与恢复.md) §4.2 还原，**不要** re-DKG |
| 治理提案被误批 | 立即提交收紧提案（暂停/降限额）——收紧无时间锁；放松类才需要等 |
| 备份损坏或过期 | 先 `restore_backup.sh --dry-run` 校验包；按 [02-2-备份与恢复.md](02-2-备份与恢复.md) 选择整组还原路径，不要用坏包先毁现场 |

提现加价（仅 BTC 提现、RGB20 不支持）、放弃提现、治理暂停等操作命令见
[02-5-治理与日常操作.md](02-5-治理与日常操作.md)。监控关键字与告警阈值见
[02-3-监控与告警.md](02-3-监控与告警.md)。
