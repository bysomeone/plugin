# 治理与日常操作

本文只列运维会执行的命令与动作。治理字段的含义、生效配置的合并口径与符号规则见
[CONFIG.md](../../plugin/dapp/lightclient/rpc/lightclient/neutrino/CONFIG.md) §4.4.5 与
[03-前端对接.md](03-前端对接.md) §1、§2。

## 1. 查询

```bash
# 某资产的**生效**配置（全局记录 + 资产记录合并；判断限额、暂停、手续费用它）
chain33-cli rgbx get-effective-bridge-config --asset-symbol RGB20_USDT

# 原始治理记录（单条、不合并；排查治理记录本身时用，空 = 从未配置）
chain33-cli rgbx get-bridge-config --asset-symbol RGB20_USDT
```

不要用 `get-bridge-config` 的原始记录判断"现在限额是多少"——它不包含全局主开关与全局暂停的合并。
`get-effective-bridge-config` 的返回字段与合并规则见
[03-前端对接.md](03-前端对接.md) §2。

## 2. 提案与审批

治理是两步：`bridge-config-apply` 提案 → autonomy 董事会审批 → `bridge-config-approve` 落地。

```bash
# 提案：设置限额 / 暂停 / 手续费（示例：单笔上限）。治理用**原始符号**（BTC / RGB20_USDT）
chain33-cli rgbx bridge-config-apply --asset-symbol BTC --max-per-tx 100000000 --fields maxPerTx

# 董事会审批通过后，由提案人提交
chain33-cli rgbx bridge-config-approve --apply-id <applyTxHash> --item-id <autonomyItemId>
```

- **`--fields` 是字段掩码**：只改部分字段时必须给，否则未点名的字段会被按 0 重置（全量快照）。
- **时间锁**：收紧（暂停、降限额、提费、关限额开关）立即生效；放松（解暂停、提限额、降费）等
  14400 区块（约 24h）后惰性生效；新的收紧提案会取消未生效的放松。
- 首次配置（链上还没有任何生效配置）立即生效。
- `get-effective-bridge-config` 的 `pendingActivationHeight > 0` 表示有一条放松正在时间锁中，
  到该高度前 `config` 仍是旧值。

## 3. 暂停与解暂停

```bash
# 暂停充值（全组生效；加 --asset-symbol 可只针对某个资产）
chain33-cli rgbx bridge-config-apply --pause-deposit=true --fields pauseDeposit

# 解暂停（放松方向，受 24h 时间锁）
chain33-cli rgbx bridge-config-apply --pause-deposit=false --fields pauseDeposit
```

- 禁用/启用资产用暂停开关（`pauseDeposit` / `pauseWithdraw`），**不要**靠改配置模板或重启桥。
- 暂停是链上治理状态，全组节点一致；单节点急停见 §7。

## 4. RGB20 提现手续费

```bash
# 提案：把 RGB20_USDT 的固定手续费设为 1000 个最小单位
chain33-cli rgbx bridge-config-apply \
  --asset-symbol RGB20_USDT \
  --rgb20-withdraw-fee RGB20_USDT=1000 \
  --fields rgb20WithdrawFee
```

用户侧口径：提现时用户自己开的 invoice 金额必须是 `提现额 − 手续费`。桥按精确相等校验，多给/少给
都会在签名与广播之前拒绝。手续费来源、校验点与失败语义的权威说明见
[CONFIG.md](../../plugin/dapp/lightclient/rpc/lightclient/neutrino/CONFIG.md) §4.4.5。

## 5. BTC 提现加价

仅 BTC 提现支持，RGB20 不支持：

```bash
chain33-cli rgbx bump-withdraw-fee --withdrawal-tx-hash <burnTxHash> --fee-rate 12
```

`--fee-rate` 单位是 sat/vB，必须高于原费率。它会要求桥以更高费率重签一笔尚未结算的提现。

## 6. 放弃提现

```bash
chain33-cli rgbx abandon-withdraw \
  --burn-tx-hash <withdrawTxHashHex> \
  --owner <refundAddress> \
  --reason "stuck for too long"
```

- 只用于**尚未结算**的提现；`--owner` 必须与 burn 台账记录的退款地址完全一致（防手误）。
- 一旦已经签名并广播，只能继续结算，不能放弃；锁定/解锁的完整语义见
  [WITHDRAW_LOCK_MODEL.md](../../plugin/dapp/lightclient/rpc/lightclient/neutrino/WITHDRAW_LOCK_MODEL.md)。

## 7. 节点本地急停

不改治理、改完重启对应节点即生效：

| 配置 | 作用 |
| --- | --- |
| `rgb20.safety.disableDeposits` | 该节点停止处理新充值 |
| `rgb20.safety.disableWithdrawals` | 该节点停止签新提现 |

已广播提现的确认与解锁不受影响。本地急停只作用于该节点；要让全组停止，用 §3 的治理暂停。

## 8. 自动熔断

同一节点在若干笔**不同** burn 上被判"实发金额不符"后停止签新提现（默认 3 笔，
`safety.maxPayoutMismatchBurns`）。熔断**不自恢复**：修好配置/账本后重启节点才继续。触发后会打印
`ALERT withdrawal circuit breaker tripped`，处置见 [02-4-应急预案.md](02-4-应急预案.md)。
